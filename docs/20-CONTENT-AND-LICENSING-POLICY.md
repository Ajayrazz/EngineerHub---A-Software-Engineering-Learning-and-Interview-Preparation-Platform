# 20 — Content & Licensing Policy

Status: **Adopted per product-owner decision (2026-11-23).** This is an engineering policy, not legal advice; items marked ⚖ should be confirmed with a lawyer before public launch.

## 1. Principles
EngineerHub is an independent brand. We cover the same *kinds* of topics (arrays, graphs, DP, system design…), learning paths and problem categories as other platforms, but every piece of published content must be **original or properly licensed**.

## 2. Allowed sources
| Source | Allowed? | Rules |
|---|---|---|
| Original content written by us / our contributors | ✅ | Contributor agreement assigns or licenses content to EngineerHub |
| Algorithms, data structures, and general concepts | ✅ | Ideas/algorithms aren't copyrightable; our **wording, examples, diagrams, code** must be our own |
| Original problems *inspired by* classic patterns (e.g. "find two numbers summing to a target") | ✅ | New title, new statement, new examples, new tests. Do not reuse another site's exact wording, examples, or numbering |
| Openly licensed material (CC0, CC BY, CC BY-SA, MIT, etc.) | ✅ with care | Record license + attribution in `content_sources`; CC BY-SA is share-alike and may constrain our own licensing — default to CC0/CC BY/MIT only ⚖ |
| Public-domain / government / textbook-expired works | ✅ | Record provenance |
| AI-assisted drafts | ✅ with care | Human-reviewed for correctness and originality; never paste third-party text into prompts to "rewrite" it; mark `ai_assisted=true` in metadata ⚖ (AI output ownership rules vary) |
| Other platforms' problem statements, editorials, lessons, test data, animations, testimonials, creator bios, logos, UI copy | ❌ | Copying/closely paraphrasing is not permitted |
| Linking out to an external problem (e.g. "similar problem on another site") | ✅ | Title + URL only; no copied text; use sparingly, and `rel="noopener noreferrer"` |
| Scraped data | ❌ | |
| Company-wise tags / frequencies | ⚠ | Source from our own user reports/aggregated analytics only; show disclaimer ("community-reported, not verified"); don't import third-party lists ⚖ |

## 3. Data-model support
- `content_sources(id, entity_type, entity_id, kind CHECK(original|licensed|open_license|ai_assisted), license, attribution, source_url, reviewed_by, reviewed_at)`.
- Publishing gate: a lesson/problem cannot move to `published` without a `content_sources` row and reviewer sign-off (enforced in the publish workflow, LMS-015/PROB-008).
- Authors confirm originality on submit (checkbox recorded in audit log).

## 4. Problem-authoring rules
1. Write the statement from scratch; do not start from another site's text.
2. Change the scenario, constraints, and examples; verify with similarity check against a prohibited-sources list (manual at first).
3. Tests are generated by us (generator + reference solution + brute-force cross-check).
4. Reference solutions and editorials are written by us.

## 5. Branding rules
No use of AlgoMaster/LeetCode/GeeksforGeeks names, logos, color schemes, or layouts as ours. Third-party names may appear only as plain-text factual references (e.g. company names in company tags — ⚖ trademark nominative use) without logos until reviewed.

## 6. Takedown & user content
ToS + DMCA-style/IT-Rules-compliant takedown process for user-generated content; community content license grant from users; moderation workflow in COMM-003. ⚖ India's IT Act / Intermediary Rules applicability to be confirmed.

## 7. Content production reality
Content is the largest effort (see doc 16 "Content track"). Pipeline: topic outline → author draft → technical review → originality check → publish. Tooling (CMS, problem validation harness, visualization trace library) is built *before* bulk content.

## 8. Authoring workflow: owner + Claude (confirmed 2026-11-23)

The project owner authors all content; Claude assists with research, drafting, structuring, reviewing and validating. **The owner is the accountable final reviewer of everything published.**

**Pipeline per item:** outline → Claude-assisted draft (from our own outline/notes, never from pasted third-party text) → owner edit → technical review → originality check → validation → publish.

**Rules**
1. **Never paste copyrighted material** (LeetCode/GeeksforGeeks/etc. statements, editorials, lessons) into prompts to be "rewritten" or "inspired by". Describe the *concept* and the *pattern* instead; let Claude propose a new scenario.
2. **Correctness is verified by machines, not by trust:** for every problem, expected outputs come from a *reference solution* validated against an independent *brute-force* solution on generated tests (the validation harness, Phase 3). AI-written expected outputs/editorial claims are never published unverified. Complexity claims are checked.
3. **Code in lessons/editorials is executed** in the judge (or CI) in all published languages before publish.
4. **Originality check:** owner reviews for resemblance to known problems/phrasing; records `content_sources` (`kind=ai_assisted` where applicable). Search-engine spot checks of distinctive sentences. Items that closely mirror a known problem are rewritten or dropped.
5. **Factual review checklist:** definitions, complexity, edge cases, constraints consistent with tests, examples correct, no unsafe advice, clear for the target level.
6. **Visualizations** are produced from deterministic, unit-tested traces (ADR-009), not AI output.
7. **Quizzes:** answers/explanations double-checked by running the code or reasoning independently.
8. **Admin/CMS requirements derived from this workflow** (Phase 2–3): draft/preview/publish states, content-source metadata, review checklist per item, bulk import/export (Markdown + JSON) so drafting can happen in Antigravity/Git, versioning, validation status badges (e.g. "tests verified ✔ / not verified").
9. Legal questions about AI-assisted content ownership remain ⚖ for a lawyer.
